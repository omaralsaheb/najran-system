# Najran Agency — نظام إدارة الوكالة

## تحديث الواجهة المؤسسية

- واجهة أحدث بخط DIN (مع بديل عربي تلقائي)، حركات انتقال ناعمة، وتصميم متجاوب.
- أيقونات Flaticon UIcons 4 في القائمة والأزرار والخدمات، مع رابط النسب المطلوب.
- مركز خدمات الشركة: حضور وانصراف، طلبات إجازة ومشتريات وصيانة، موافقات، وإعلانات داخلية.
- تواصل داخلي مباشر: دردشة عامة لكل الموظفين، ومحادثات خاصة بين موظفين اثنين.
- إعلانات رسمية تنشرها الإدارة وتظهر للموظفين داخل مركز التواصل.
- صفحة رئيسية للموظف: المهام الجارية، تقويم الشهر، إنجاز اليوم والأسبوع، والفريق المتصل لحظياً.
- صفحة تفاصيل لكل مهمة مع بدء، إيقاف مؤقت، إنهاء وتسليم عبر واتساب أو رابط Google Drive، وحذف للإدارة.
- وضع داكن وفاتح، وخمسة ثيمات ألوان، وواجهة عربية/إنجليزية مع دعم RTL وLTR.
- زر إجراء سريع لإضافة مهمة أو عميل أو موظف أو طلب داخلي من أي صفحة.

نظام إدارة داخلي للوكالة: عملاء، مهام، فريق، محتوى، ومالية — **HTML + CSS +
JavaScript صافي** (بدون أي إطار عمل ولا خطوة بناء)، وقاعدة البيانات والتوثيق
على **Firebase**.

## شو صار حقيقي هلق

كل شي محفوظ على Firebase Realtime Database — **ما في ولا بيان بيضيع لما تسكر
الصفحة**:

| الجزء | الحالة |
|---|---|
| تسجيل الدخول | باسم مستخدم وكلمة سر — جلسة بتضل محفوظة بعد ما تسكر المتصفح |
| الدخول المؤقت | رمز سري مشترك بصلاحيات محدودة، بينوقف بضغطة |
| الموظفين والصلاحيات | محفوظين، وإضافة موظف بتنشئ حساب دخول حقيقي |
| المهام | محفوظة + صفحة تفاصيل + إجراءات الحالة والتسليم + سجل دائم لكل تغيير |
| **العملاء** | محفوظين + حالة نشط/غير نشط + حذف إداري آمن مع إبقاء سجل المهام |
| **المحتوى والتحليلات** | محفوظين (كانوا بيضيعوا) |
| **المالية** | محفوظة + سجل دائم لكل تعديل (مين عدّل وشو كانت الأرقام) |
| **الدردشة العامة والخاصة** | رسائل مباشرة محفوظة ومحمية بقواعد Firebase |
| **إعلانات الإدارة** | محفوظة وتظهر لكل الموظفين، والنشر للإدارة فقط |
| **الإشعارات** | لحظية مع صوت للمهام الجديدة والمحادثات والإعلانات، وإشعار نظام عند السماح به |
| **حالة اتصال الفريق** | تتحدث لحظياً، ويُسجل آخر اتصال عند إغلاق الموقع |
| **المظهر واللغة** | محفوظان على جهاز المستخدم ويتذكرهما الموقع تلقائياً |
| **البريف وربط ميتا** | محفوظين (كانوا بيضيعوا) |

## بنية المشروع

```
public/                    ← هاد يلي بينرفع (مجلد الموقع)
├── index.html             ← هيكل الصفحات الثلاثة (الرئيسية، الدخول، الداشبورد)
├── css/styles.css         ← كل التنسيقات
└── js/
    ├── main.js            ← نقطة البداية: بتربط الأزرار بالدوال وتشغّل كل شي
    ├── firebase.js        ← الاتصال بـFirebase
    ├── store.js           ← طبقة البيانات — كل قراءة/كتابة بتمر من هون بس
    ├── state.js           ← الحالة المشتركة + الأدوار والصلاحيات الأساسية
    ├── auth.js            ← الدخول، الإعداد الأول، الخروج
    ├── ui.js              ← الرسم، التنقل، المودالات، الإشعارات، البحث
    ├── i18n.js            ← التبديل بين العربية والإنجليزية
    ├── preferences.js     ← الداكن/الفاتح وثيمات الألوان
    ├── landing.js         ← أنيميشن الشعار ثلاثي الأبعاد
    ├── logo.js            ← الشعار (base64)
    └── pages/             ← صفحة لكل قسم
        ├── clients.js     ← نظرة عامة + صفحة العميل + المحتوى + التقارير
        ├── tasks.js       ← المهام + لوحتي + التقويم
        ├── team.js        ← الفريق
        ├── home.js        ← الرئيسية وملخص الموظف وحالة اتصال الفريق
        ├── chat.js        ← الدردشة العامة والخاصة وإعلانات الإدارة
        ├── finance.js     ← المالية
        └── settings.js    ← الصلاحيات والمسميات وربط ميتا
netlify.toml               ← إعدادات النشر على Netlify
vercel.json                ← إعدادات النشر على Vercel (بديل)
firebase.json              ← إعدادات Firebase (بديل الاستضافة + القاعدة)
database.rules.json        ← قواعد الأمان (مين بيقدر يقرأ/يكتب شو)
.firebaserc                ← اسم مشروع Firebase
```

**قاعدة مهمة بالكود:** ما في ولا استدعاء لـFirebase برّا `store.js`. أي صفحة
بدها بيانات بتنادي دالة من `store.js`.

## الرفع — بالترتيب

الاستضافة على **Netlify** (ملفات الموقع)، وFirebase بيضل بس **قاعدة البيانات
والتوثيق**. ما بتحتاج تركّب ولا أداة على جهازك.

### 1. فعّل تسجيل الدخول بلوحة Firebase

[console.firebase.google.com](https://console.firebase.google.com) ← مشروع
`najran-system`:

**Authentication** ← **Get started** ← **Sign-in method** ← فعّل **Email/Password**

*(بدون هالخطوة ما في تسجيل دخول أبداً — بيرجع خطأ `configuration-not-found`)*

### 2. الصق قواعد الأمان ← **أهم خطوة بالملف كله**

**Realtime Database** ← تبويب **Rules** ← امسح يلي فيه والصق محتوى
`database.rules.json` كامل ← **Publish**

**بدون هالخطوة النظام بيشتغل عادي بالظاهر — بس بلا حماية إطلاقاً.** الوضع
الافتراضي للقاعدة بيسمح لأي حساب مسجّل دخول (وبضمنهم الدخول المؤقت بالرمز) إنه
يقرأ ويكتب **كل شي** من كونسول المتصفح: الموظفين، المالية، الصلاحيات. إخفاء
الأزرار بالواجهة مو حماية.

### 3. ⚠️ ضيف رابط الموقع لقائمة النطاقات المسموحة

**هاي أكتر خطوة بتنتسى وبتوقّف كل شي.** Firebase بيرفض تسجيل الدخول من أي نطاق
مو مسجّل عنده — حتى لو كل شي تاني مضبوط.

**Authentication** ← **Settings** ← **Authorized domains** ← **Add domain**
← حط رابط موقعك بدون `https://`، حسب وين ناشر:

```
اسم-مشروعك.netlify.app
```

⚠️ **لو غيّرت المنصة أو حذفت الموقع وأنشأته من جديد، الرابط بيتغيّر** — لازم
تضيف الرابط الجديد هون، وإلا تسجيل الدخول بيفشل مباشرة.

المنصتين بيعطوا روابط preview لكل فرع (`deploy-preview-1--الموقع.netlify.app`
بـNetlify، و`...-git-branch.vercel.app` بـVercel). تسجيل الدخول ما بيشتغل
عليهم إلا إذا ضفتهم كمان — لو ما بتشتغل على فروع، تجاهلها.

*(ولو ربطت نطاق خاص لاحقاً، ضيفه هون كمان)*

### 4. ارفع الموقع

المشروع موقع ثابت بالكامل — ما في خطوة بناء ولا متغيرات بيئة. اربط المستودع من
GitHub وبس؛ الإعدادات بتنقرأ لحالها. أي push جديد بيعيد النشر لحاله.

| المنصة | ملف الإعداد | مجلد النشر |
|---|---|---|
| **Netlify** (المستعملة حالياً) | `netlify.toml` | `public` |
| **Vercel** | `vercel.json` | `public` |

الملفين موجودين سوا؛ كل منصة بتقرأ ملفها وبتتجاهل التاني — فالتنقل بيناتهم
ما بيحتاج ولا تعديل بالكود.

> **ليش الملف ضروري:** ملفات الموقع جوا `public/` مش بالجذر. بدون هالإعداد
> المنصة بتدوّر على `index.html` بالجذر وما بتلاقيه، فبتطلع صفحة **404**.

### 5. أنشئ حساب المدير الأول

افتح رابط الموقع ← **تسجيل الدخول**. بما إنه ما في ولا حساب بعد، الشاشة رح
تتحول تلقائياً لفورم **"إعداد النظام لأول مرة"**:

| الخانة | شو تحط |
|---|---|
| اسمك الكامل | بالعربي عادي — هاد يلي بيظهر بالنظام |
| اسم المستخدم | أحرف إنجليزية وأرقام و `. _ -` بس، مثلاً `anas` |
| كلمة السر | 6 أحرف عالأقل |
| رمز الدخول المؤقت | 6 أرقام — جاي معبّى `310126`، غيّره لو بدك |

هالخطوة بتعمل تلقائياً:
- حسابك كـ"المدير العام والتنفيذي"
- حساب الدخول المؤقت بالرمز
- الأدوار التسعة الأساسية بصلاحياتها

**بتشتغل مرة وحدة بس** — بعدها القواعد بترفض أي محاولة تانية لإنشاء مدير.

### 6. ضيف الموظفين

من صفحة **الفريق** ← **+ إضافة موظف**: الاسم، اسم المستخدم، كلمة سر مبدئية،
والدور. كل موظف بينعمله حساب دخول حقيقي، وبتعطيه الرابط واسم المستخدم وكلمة
السر — وبيفوت من أي جهاز.

**ما في تسجيل ذاتي بالنظام أبداً** — إنت بس يلي بتنشئ الحسابات.

## الأمان — شو محمي وكيف

مفتاح Firebase (`apiKey`) موجود بالكود وهاد **طبيعي ومقصود** — مفاتيح الويب مو
أسرار. الحماية الحقيقية كلها بـ`database.rules.json`، والقواعد بتنفّذ على
سيرفرات Firebase مش بالمتصفح، يعني ما بينفع حدا يتحايل عليها من أدوات المطوّر:

| المسار | مين بيقرأ | مين بيكتب |
|---|---|---|
| `meta/initialized` | الكل (بوليان بس) | مرة وحدة، وقت الإعداد الأول |
| `roles` | أي موظف مسجّل | صاحب صلاحية `settings` بس |
| `employees` | أي موظف مسجّل | صاحب صلاحية `team` بس |
| `clients` | أي موظف مسجّل | الإضافة والتحديث لصاحب `overview`؛ الحذف لصاحب `settings` فقط |
| `tasks` | أي موظف مسجّل | الإنشاء والتحديث لأي موظف؛ الحذف لصاحب صلاحية `settings` فقط |
| `content` | أي موظف مسجّل | أي موظف مسجّل |
| `taskActivity` | أي موظف مسجّل | **إضافة بس** — ما بينعدّل ولا بينحذف |
| `generalChat` | الموظفون الفعّالون فقط | إضافة رسالة باسمه فقط |
| `privateChats` | طرفا المحادثة فقط | كل طرف يضيف رسائله فقط |
| `announcements` | الموظفون الفعّالون فقط | الإدارة فقط |
| `presence` | الموظفون الفعّالون فقط | كل موظف يحدّث حالته فقط |
| `finance` / `financeActivity` | صاحب صلاحية `finance` بس | صاحب صلاحية `finance` بس |

حساب الدخول المؤقت بياخد دور `temp_access` — نفس القواعد بتنطبق عليه، يعني
المالية والإعدادات ودردشات الموظفين محجوبة عنه من طرف Firebase مش بس مخفية بالواجهة.

يعني حتى لو موظف فتح أدوات المطوّر وحاول يقرأ المالية، Firebase نفسه بيرفض.

**ملاحظة:** القواعد انراجعت بالكود بس ما انجرّبت على قاعدة حية بعد. أول ما
ترفعها، جرّب تسجّل دخول بحساب موظف عادي وشوف إنه فعلاً ما بيشوف المالية.

## تسجيل الدخول — كيف بيشتغل

Firebase Authentication ما بيدعم اسم مستخدم مباشرة — بيدعم بريد إلكتروني بس.
فمنركّب بريد داخلي من اسم المستخدم:

```
anas  ←→  anas@najran-system.local
```

الموظف ما بيشوف هالبريد أبداً — بيكتب `anas` وبس. وفايدة إضافية: Firebase
بيمنع تكرار البريد، يعني **تفرّد اسم المستخدم مضمون من غير ما نكتب سطر كود**.

### الدخول المؤقت بالرمز

الرمز السري هو **كلمة سر حساب مخصص** اسمه `access`. يعني الرمز:
- ما هو مكتوب بالكود ولا محفوظ بالقاعدة — Firebase بيتحقق منه متل أي كلمة سر
- بينتغيّر من **الإعدادات ← الدخول المؤقت ← تغيير الرمز**
- بينوقف بضغطة وحدة من نفس الصفحة

**⚠️ حدوده — اقرأها قبل ما توزّعه:**
- أي حدا معه الرمز بيفوت، وما بتعرف مين — ما في مساءلة
- الرمز الافتراضي `310126` مكتوب بفورم الإعداد الأول، يعني ظاهر لأي حدا بيفتح
  كود الصفحة. **غيّره من الإعدادات بعد ما تخلّص الإعداد**
- صلاحياته محدودة عن قصد: لوحتي، نظرة عامة، المهام، التقويم — **بدون** فريق ولا
  مالية ولا إعدادات
- ما بيظهر بصفحة الفريق ولا بقوائم إسناد المهام

استعمله للعرض والتجربة والوصول السريع — الشغل اليومي بحسابات شخصية.

### نسيان كلمة السر

ما في "أرسل رابط استرجاع" لأنه البريد داخلي وما بيوصله إيميل. البدائل:
- **المستخدم بيغيّرها بنفسه** من رابط "تغيير كلمة السر" بالسايدبار (لازم يعرف القديمة)
- **نسيها كلياً؟** المدير بيوقف الحساب من الفريق وبينشئ واحد جديد باسم مستخدم
  جديد. إعادة التعيين الحقيقية بتحتاج Cloud Function بخطة Blaze

## إضافة موظف — كيف بتشتغل

Firebase بيسجّل دخول أي حساب جديد تلقائياً، يعني إنشاء موظف كان رح يطلّع المدير
من جلسته. الحل بـ`store.js`: منعمل **نسخة تانية من تطبيق Firebase** مخصصة
للإنشاء بس، ومنسكرها بعدها — وجلسة المدير بتضل متل ما هي.

## الاحتفاظ بالبيانات

ما في أي سكربت حذف تلقائي بالكود:
- `taskActivity` — القواعد نفسها بتمنع التعديل والحذف (إضافة بس)
- `financeActivity` — نفس الشي، سجل دائم لكل تعديل مالي
- الموظفين ما بينحذفوا — بينوقفوا (`active: false`) حتى تضل مهامهم مربوطة باسم

## Meta API — لسا مو مربوط

تبويب "ربط حسابات ميتا" بالإعدادات بيحفظ اسم الصفحة و Instagram Business
Account ID بس. سحب الأرقام الحقيقي بده:

1. تطبيق مسجّل على [developers.facebook.com](https://developers.facebook.com)
2. ربطه بحساب Meta Business تبع الوكالة
3. موافقة **App Review** على `instagram_manage_insights` — بياخد أسابيع
4. موافقة رسمية من كل عميل (Facebook Business Login)

**وملاحظة أمنية:** ما حطينا خانة Access Token بالفورم عن قصد — التوكن سر، ولو
انحفظ بالقاعدة رح يكون مقروء من أي موظف مسجّل دخول. محله لما يجي وقته Cloud
Function بمفاتيح مخفية على السيرفر.
