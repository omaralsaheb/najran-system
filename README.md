# Najran Agency — نظام إدارة الوكالة

## ✅ الحالة الحالية: تسجيل دخول + موظفين + صلاحيات + مهام = مربوطين وشغالين فعلياً

- تسجيل دخول حقيقي بإيميل وكلمة سر
- **إعداد أول مرة من المتصفح مباشرة** — أول ما يشتغل السيرفر وما في ولا موظف
  مسجل، شاشة الدخول بتتحول تلقائياً لفورم "أنشئ حساب المدير الأول" (بدون
  تيرمنال ولا سكربت — بس تعبي اسمك وإيميلك وكلمة سر)
- الموظفين، الصلاحيات، **والمهام** محفوظين بقاعدة بيانات حقيقية (PostgreSQL) —
  ما بيضيعوا
- تعديل موظف موجود (الاسم والمسمى الوظيفي) — مو بس إضافة
- تعديل أي مهمة بأي وقت، **حتى لو صارت "مكتمل"** — مع خانة ملاحظات لكل مهمة
- المدير يقدر يعرّف **مسميات وظيفية جديدة بصلاحياتها** من الإعدادات، مش بس
  يختار من قائمة ثابتة بالكود
- **المالية** — تظهر لصاحب دور "المدير العام والتنفيذي" بس
- إضافة موظف جديد مقصورة على صاحب صلاحية "الفريق" (المدير، مديرة العمليات،
  والمنسقة الإدارية/السكرتير) — محروسة من طرف السيرفر نفسه مش بس مخفية بالواجهة
- الفرونت إند والباك إند **برنامج واحد**: سيرفر واحد بيخدم الاثنين معاً
- شعار الوكالة الحقيقي متضمّن بالملف (بصيغة base64) — بالسايدبار، شاشة الدخول،
  وبالأنيميشن ثلاثي الأبعاد بالصفحة الرئيسية
- **البيانات التجريبية انمسحت بالكامل** — النظام بيبلش فاضي، جاهز تدخل بياناتك
  الحقيقية

**لسا محلياً (مش مربوط بقاعدة البيانات):** العملاء، المحتوى/التحليلات،
والمالية — هاي القطاع الجاي.

## بنية المشروع

```
najran-system/
├── backend/
│   ├── db/schema.sql   ← كل الجداول + الأدوار الأساسية (بدون أي حذف تلقائي)
│   ├── db/seed.js      ← بديل اختياري لإنشاء أول حساب مدير عبر التيرمنال
│   ├── routes/         ← auth, employees, clients, tasks, content, finance
│   ├── services/       ← الربط مع Meta Graph API
│   ├── app.js          ← تطبيق Express لحاله (بينستعمل بالحالتين تحت)
│   └── server.js       ← سيرفر عادي: بيخدم الواجهة **و** الـAPI، بورت واحد بس
├── frontend/
│   └── index.html      ← الواجهة (مربوطة فعلياً بتسجيل الدخول، الموظفين، والمهام)
├── netlify/functions/
│   ├── api.js          ← نفس الباك إند بس شغال كـfunction على Netlify
│   └── meta-sync.js    ← المزامنة الدورية مع Meta (مجدولة كل 6 ساعات)
├── netlify.toml        ← إعدادات Netlify (وين الواجهة، وين الـAPI)
└── package.json        ← مكتبات المشروع + `npm start`
```

## خطوات الرفع — بالترتيب

### 1. قاعدة البيانات (PostgreSQL)
أسهل خيارين:
- **Supabase** (supabase.com) — خطة مجانية، وفيها محرر SQL تلصق فيه الكود مباشرة
- **Railway** (railway.app) — بتضيف Postgres بضغطة زر جنب السيرفر نفسه

بعد ما تنشئها، افتح محرر الـSQL وشغّل محتوى `backend/db/schema.sql` مرة وحدة كاملة.

### 2. متغيرات البيئة
جوا `backend/`، انسخ `.env.example` باسم `.env` واملأ:
- `DATABASE_URL` — الرابط يلي بيديك ياه Supabase/Railway
- `JWT_SECRET` — أي نص عشوائي طويل (لتشفير جلسات الدخول)
- `META_ACCESS_TOKEN` — اتركها فاضية لهلق، لاحقاً بعد ما يتوافق التطبيق عند Meta

### 3. تشغيل السيرفر وإنشاء أول حساب مدير
```
npm install
npm start
```
افتح `http://localhost:4000` (أو رابط السيرفر بعد الرفع) — بما إنه ما في ولا
موظف مسجل بعد، الشاشة رح تطلعلك فورم "إعداد النظام لأول مرة" مباشرة: حط اسمك،
إيميلك، وكلمة سر، ودوس "إنشاء حساب المدير". بعدها بترجع تلقائياً لفورم تسجيل
الدخول العادي وتقدر تدخل فيهم.

*(بديل من التيرمنال لو حبيت: `npm run seed` بينشئلك حساب جاهز
`admin@najranagency.com` / `Najran@2026` — بس غيّر كلمة السر فوراً.)*

### 4. الرفع الفعلي — Netlify

المشروع صار مجهّز لـNetlify: الواجهة بتتنشر كملفات ثابتة، والباك إند بيشتغل
كـ**Netlify Function** (بدون سيرفر دائم). الملفات المسؤولة: `netlify.toml`
و`netlify/functions/`.

الخطوات:
1. ارفع المشروع **كامل** (المجلد الجذر، مش `frontend/` لحاله) على GitHub،
   وبNetlify اختار **Add new site → Import an existing project**.
   *(الرفع بالسحب والإفلات ما بينفع هون — لأن الفنكشن بدها `npm install`.)*
2. إعدادات البناء بتنقرأ تلقائياً من `netlify.toml` — ما تغيّر شي:
   - Publish directory: `frontend`
   - Functions directory: `netlify/functions`
   - Build command: `npm install`
3. **Site configuration → Environment variables** — ضيف نفس متغيرات خطوة 2:
   `DATABASE_URL` و`JWT_SECRET` (و`META_ACCESS_TOKEN` فاضي لهلق).
   بدون `DATABASE_URL` الواجهة رح تفتح بس تسجيل الدخول رح يفشل.
4. اضغط **Deploy** — بعدها افتح الرابط واعمل خطوة الإعداد الأول (خطوة 3 فوق).

للتأكد إنه الباك إند شغال: افتح `https://<اسم-الموقع>.netlify.app/api/health`
لازم يطلعلك `{"ok":true}`.

**بديل — Railway أو Render** (سيرفر عادي، وبيشتغل فيه `node-cron` مباشرة):
- اربط الـrepo من الجذر
- ضيف متغيرات البيئة (خطوة 2)
- Build: `npm install` — Start: `npm start`

بعد الرفع رح ياخد المشروع كامل (واجهة + تسجيل دخول + كل شي) رابط واحد ثابت —
هاد الرابط هو "البرنامج" كامل، ما في ملف تاني لازم ترفعه لحاله.

## العملاء، المحتوى/التحليلات، المالية — لسا الخطوة الجاية

هاي الأجزاء شغالة بالواجهة لكل اللي يسجل دخول، بس البيانات لسا بتضيع لما
تسكر الصفحة (نفس منطق النموذج التجريبي الأول). **المهام والموظفين صاروا
حقيقيين بالكامل** — الباقي (العملاء، المحتوى، المالية) الباك إند جاهز أصلاً
له (`routes/clients.js`, `routes/finance.js`, `routes/content.js`) — نفس نمط
الربط يلي صار للمهام والفريق، يطبق عليهم بنفس الطريقة.

## Meta API — قبل ما يشتغل الربط الحقيقي

1. سجل تطبيق على [developers.facebook.com](https://developers.facebook.com)
2. اربطه بحساب Meta Business تبع الوكالة
3. قدّم طلب **App Review** لصلاحية `instagram_manage_insights` — بياخد وقت (أسابيع)
4. كل عميل لازم يوافق رسمياً (Facebook Business Login) قبل ما تقدروا تسحبوا بياناته

## ملاحظة مهمة عن الاحتفاظ بالبيانات

كل الإحصائيات (`content` + `analytics_history`) **محفوظة دائماً** — ما في أي
سكربت حذف تلقائي بالكود. المزامنة الدورية (كل 6 ساعات) بتضيف سجلات جديدة بس،
وما بتمسح القديم أبداً.

## المالية (Finance)

جدول `client_finance` فيه رقمين لكل عميل: `advance_paid` (مدفوع مقدماً) و
`extra_expenses` (مصاريف زائدة) — والمجموع بيتحسب دايماً من الاثنين. كل تعديل
بينسجل بجدول `finance_activity` كسجل دائم — مين عدّل، وشو كانت الأرقام وقتها.
