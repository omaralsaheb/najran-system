# Najran Agency — نظام إدارة الوكالة

نظام إدارة داخلي للوكالة: عملاء، مهام، فريق، محتوى، ومالية — **HTML + CSS +
JavaScript صافي** (بدون أي إطار عمل ولا خطوة بناء)، وقاعدة البيانات والتوثيق
على **Firebase**.

## شو صار حقيقي هلق

كل شي محفوظ على Firebase Realtime Database — **ما في ولا بيان بيضيع لما تسكر
الصفحة**:

| الجزء | الحالة |
|---|---|
| تسجيل الدخول | Firebase Authentication — جلسة بتضل محفوظة بعد ما تسكر المتصفح |
| الموظفين والصلاحيات | محفوظين، وإضافة موظف بتنشئ حساب دخول حقيقي |
| المهام | محفوظة + سجل دائم لكل تغيير حالة |
| **العملاء** | محفوظين (كانوا بيضيعوا) |
| **المحتوى والتحليلات** | محفوظين (كانوا بيضيعوا) |
| **المالية** | محفوظة + سجل دائم لكل تعديل (مين عدّل وشو كانت الأرقام) |
| **البريف وربط ميتا** | محفوظين (كانوا بيضيعوا) |

## بنية المشروع

```
public/                    ← هاد يلي بينرفع على Firebase Hosting
├── index.html             ← هيكل الصفحات الثلاثة (الرئيسية، الدخول، الداشبورد)
├── css/styles.css         ← كل التنسيقات
└── js/
    ├── main.js            ← نقطة البداية: بتربط الأزرار بالدوال وتشغّل كل شي
    ├── firebase.js        ← الاتصال بـFirebase
    ├── store.js           ← طبقة البيانات — كل قراءة/كتابة بتمر من هون بس
    ├── state.js           ← الحالة المشتركة + الأدوار والصلاحيات الأساسية
    ├── auth.js            ← الدخول، الإعداد الأول، الخروج
    ├── ui.js              ← الرسم، التنقل، المودالات، الإشعارات، البحث
    ├── landing.js         ← أنيميشن الشعار ثلاثي الأبعاد
    ├── logo.js            ← الشعار (base64)
    └── pages/             ← صفحة لكل قسم
        ├── clients.js     ← نظرة عامة + صفحة العميل + المحتوى + التقارير
        ├── tasks.js       ← المهام + لوحتي + التقويم
        ├── team.js        ← الفريق
        ├── finance.js     ← المالية
        └── settings.js    ← الصلاحيات والمسميات وربط ميتا
firebase.json              ← إعدادات Hosting والقاعدة
database.rules.json        ← قواعد الأمان (مين بيقدر يقرأ/يكتب شو)
.firebaserc                ← اسم مشروع Firebase
```

**قاعدة مهمة بالكود:** ما في ولا استدعاء لـFirebase برّا `store.js`. أي صفحة
بدها بيانات بتنادي دالة من `store.js`.

## الرفع — بالترتيب

### 1. فعّل الخدمات بلوحة Firebase

افتح [console.firebase.google.com](https://console.firebase.google.com) →
مشروع `najran-system`:

1. **Authentication** → Get started → **Sign-in method** → فعّل **Email/Password**
   *(بدون هالخطوة تسجيل الدخول ما بيشتغل أبداً)*
2. **Realtime Database** → لازم تكون منشأة أصلاً (رابطها موجود بالإعدادات)

### 2. ركّب أدوات Firebase وسجّل دخول

```bash
npm install -g firebase-tools
```

```bash
firebase login
```

### 3. ارفع القواعد والموقع

من مجلد المشروع:

```bash
firebase deploy
```

هاد بيرفع شغلتين مع بعض: قواعد الأمان (`database.rules.json`) وملفات
`public/`. بعدها بيعطيك رابط: `https://najran-system.web.app`

> ⚠️ **لو ما رفعت القواعد**، الموقع رح يفتح بس شاشة الدخول رح تقلك
> "قاعدة البيانات رافضة الاتصال" — لأن Firebase بيرفض كل شي افتراضياً.

### 4. أنشئ حساب المدير الأول

افتح الرابط → **تسجيل الدخول**. بما إنه ما في ولا حساب بعد، الشاشة رح تتحول
تلقائياً لفورم **"إعداد النظام لأول مرة"**: حط اسمك، إيميلك، وكلمة سر — ودوس
"إنشاء حساب المدير".

هالخطوة بتعمل تلقائياً:
- حساب دخول على Firebase Authentication
- الأدوار الثمانية الأساسية بصلاحياتها
- حسابك كـ"المدير العام والتنفيذي"

**بتشتغل مرة وحدة بس** — بعدها القواعد بترفض أي محاولة تانية لإنشاء مدير.

## التشغيل محلياً قبل الرفع

```bash
npx http-server public -p 5173 -c-1
```

بعدين افتح `http://localhost:5173`. بيتصل بنفس قاعدة بيانات Firebase الحقيقية،
فلازم تضيف `localhost` بـ**Authentication → Settings → Authorized domains**
(عادة مضاف افتراضياً).

## الأمان — شو محمي وكيف

مفتاح Firebase (`apiKey`) موجود بالكود وهاد **طبيعي ومقصود** — مفاتيح الويب مو
أسرار. الحماية الحقيقية كلها بـ`database.rules.json`، والقواعد بتنفّذ على
سيرفرات Firebase مش بالمتصفح، يعني ما بينفع حدا يتحايل عليها من أدوات المطوّر:

| المسار | مين بيقرأ | مين بيكتب |
|---|---|---|
| `meta/initialized` | الكل (بوليان بس) | مرة وحدة، وقت الإعداد الأول |
| `roles` | أي موظف مسجّل | صاحب صلاحية `settings` بس |
| `employees` | أي موظف مسجّل | صاحب صلاحية `team` بس |
| `clients` | أي موظف مسجّل | صاحب صلاحية `overview` بس |
| `tasks` / `content` | أي موظف مسجّل | أي موظف مسجّل |
| `taskActivity` | أي موظف مسجّل | **إضافة بس** — ما بينعدّل ولا بينحذف |
| `finance` / `financeActivity` | صاحب صلاحية `finance` بس | صاحب صلاحية `finance` بس |

يعني حتى لو موظف فتح أدوات المطوّر وحاول يقرأ المالية، Firebase نفسه بيرفض.

**ملاحظة:** القواعد انراجعت بالكود بس ما انجرّبت على قاعدة حية بعد. أول ما
ترفعها، جرّب تسجّل دخول بحساب موظف عادي وشوف إنه فعلاً ما بيشوف المالية.

---

## إضافة موظف — كيف بتشتغل

Firebase بيسجّل دخول أي حساب جديد تلقائياً، يعني إنشاء موظف كان رح يطلّع المدير
من جلسته. الحل بـ`store.js`: منعمل **نسخة تانية من تطبيق Firebase** مخصصة
للإنشاء بس، ومنسكرها بعدها — وجلسة المدير بتضل متل ما هي.

---

## الاحتفاظ بالبيانات

ما في أي سكربت حذف تلقائي بالكود:
- `taskActivity` — القواعد نفسها بتمنع التعديل والحذف (إضافة بس)
- `financeActivity` — نفس الشي، سجل دائم لكل تعديل مالي
- الموظفين ما بينحذفوا — بينوقفوا (`active: false`) حتى تضل مهامهم مربوطة باسم

## Meta API — لسا مو مربوط

تبويب "ربط حسابات ميتا" بالإعدادات بيحفظ اسم الصفحة و Instagram Business
Account ID بس. سحب الأرقام الحقيقي بده:

1. تطبيق مسجّل على [developers.facebook.com](https://developers.facebook.com)
2. ربطه بحساب Meta Business تبع الوكالة
3. موافقة **App Review** على `instagram_manage_insights` — بياخد أسابيع
4. موافقة رسمية من كل عميل (Facebook Business Login)

**وملاحظة أمنية:** ما حطينا خانة Access Token بالفورم عن قصد — التوكن سر، ولو
انحفظ بالقاعدة رح يكون مقروء من أي موظف مسجّل دخول. محله لما يجي وقته Cloud
Function بمفاتيح مخفية على السيرفر.
